# 設計メモ

## 旧フローと新フローの対応

| 旧（手作業） | 新（自動） |
|---|---|
| Excel「時間割」シートに入力 | `input.json` の `timetable.grid` |
| Excel「年間」シートの年度セル | `input.json` の `schoolYear` |
| Excel「行事予定(一覧)」シート | `input.json` の `events`（`import-events` で取り込み可） |
| Excel「祝日リスト」を手入力 | `holidays.py` が年度から自動計算 |
| マクロ `複製伊神`（1週目を53枚複製） | `calendarmodel.py` が週を計算し、テンプレートが繰り返す |
| マクロ `調整伊神`（自由シート30枚） | `freePages` オプション |
| マクロ `二枚目エクスポート`（PDF出力） | `render.py`（Chromium で直接PDF化） |
| PDFリンくん（伊神モード）でリンク付与 | HTML のアンカーリンク → `postprocess.py` で実体化 |
| — | しおり・透かし・メタデータ（新規） |

旧マクロは「数式を値に変換」してから複製していたため、出来上がったファイルから
元データを復元できなかった。新方式は `input.json` を保存しておけば常に再生成できる。

## なぜ Excel をやめたか

Excel を残す案（openpyxl で53週シートを生成 → LibreOffice で PDF化）も検討したが、

- VBA はサーバーで動かないので、どのみちマクロの移植が必要
- LibreOffice の変換はフォント差で罫線や1ページ収まりが崩れやすい
- リンクを貼るために「マーカー文字を印字して後から検出する」という間接的な手順が要る

新方式では `<a href="#p12">` と書くだけでリンクになり、ページ数の検証も機械的にできる。
レイアウトの調整は `static/planner.css` を触るだけで済む。

## リンクの仕組みと落とし穴

Chromium は `<a href="#p12">` を **名前付きデスティネーション**（`/Dest /p12`）として書き出す。
PCのPDFビューアはこれを解決できるが、**モバイルの手書きアプリには解決しない実装がある**。
そのため `postprocess.py` で、ページを直接指す明示的なデスティネーションに書き換えている。

これをやらないと「PCでは飛ぶのに iPad では飛ばない」という、最もたちの悪い不具合になる。
`tests/test_build_pdf.py::test_every_link_points_to_a_real_page` がこれを守っている。

## レイアウトの前提

GoodNotes でペン書き込みをする前提のため、

- カレンダーの日付・週ページの授業名は**セルの左上に寄せる**（中央寄せにしない）。
  中央に置くと書き込みスペースが分断される。
- リンク領域は指でタップできる大きさを確保する（ナビボタンは最小22mm幅）。
- 罫線・背景は薄く。書き込んだ文字が主役。

## 行事予定の取り込み（学校ごとの形式差）

`events_import.py` は「列の意味を推測して読む」方式で、

1. 縦持ち（日付列＋行事名列）
2. 横持ち（列＝月、行＝日）

の2形式に対応する。読めなかった行は捨てずに `warnings` として返す。

**完全自動は狙っていない。** 任意フォーマット（結合セルだらけのExcel、スキャンPDF）を
100%機械で読むのは現実的でないため、「8割を機械が読んで、残りを人が直す」設計にしている。
配布用の標準テンプレート（`samples/events.sample.csv`）を購入者に埋めてもらうのが本線。

## 受注とライセンス

「PDFを守る」のではなく「**生成する権利を1回に絞る**」設計。

- 同じPDFの再配布は原理的に防げない → 透かしとメタデータで**流出元を追える**ようにする
- PDFのパスワード保護はしない（GoodNotesへの取り込みで詰まる事故のほうが確実に起きる）
- `ensure_can_generate → build → claim_generation` の順で、生成失敗時に権利を消費しない

Web フレームワークには依存していないので、Flask/FastAPI から `OrderStore` を呼ぶだけで
セルフサービス化できる。

## 既知の制限

- **旧PDF向けリンカー（`linker.py`）は best-effort。** 元の PDFリンくんのソースを
  参照せずにPDFの実物から仕様を推測したため、週ページのナビゲーションは復元できるが、
  年間カレンダー面のリンクは一部しか検出できていない。新方式では使わない。
- 祝日は法令ベースの計算。**法改正があれば `holidays.py` の修正が必要**。
- 週ページの行構成（`timetable.periods`）は全曜日共通。曜日ごとに時限数が違う日課
  （水曜だけ5限まで等）は、いまは空欄で表現する。
